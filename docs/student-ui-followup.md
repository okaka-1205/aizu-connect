# 利用者画面の追加改善

確認日: 2026-11-13

## 見つけた問題と修正

| 箇所                 | 修正内容                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| 参加予定             | 参加済み・キャンセル済み・見送り・欠席を除き、申請中・キャンセル待ち・参加確定を表示                   |
| 参加履歴             | 過去の申請・参加と、開催後アンケートをまとめて表示                                                     |
| 活動証明             | 年間記録、PDF保存、イベントごとの証明書を同じタブに集約                                                |
| 当日受付             | 成功時は履歴へ切り替え。入力エラーを受付欄と関連づけ、スマホでも拡大されにくい文字サイズへ変更         |
| イベント詳細         | 本文だけをスクロールし、閉じる・参加申請の操作を画面内に固定。説明の文字サイズと余白も整理             |
| カレンダー           | 日時が未設定の場合、Googleカレンダーも実際に操作不可にする                                             |
| 主催者の保存         | 処理中の連打を防ぎ、失敗時は操作した場所にエラーを表示                                                 |
| 通知                 | 長いタイトルの省略をやめ、未読のみの表示と外側タップでの閉じる操作を追加。処理中の重複操作を防止       |
| 通知を閉じた後       | 外側の入力欄を押した場合は、その入力欄のフォーカスを保つ。閉じるボタン・Escapeの場合は通知ボタンへ戻す |
| チャット一覧         | イベント名を主表示にして、同じ主催者のチャットを区別。検索結果が空の場合は条件を解除できるようにする   |
| チャット入力         | スマホの改行キーでは送信せず、送信ボタンで送信。メッセージ内の改行も保持して表示                       |
| 小さい画面のチャット | 成功通知や長い下書きがあっても、入力欄が下部ナビに隠れないように調整                                   |

参加予定・参加履歴・活動証明の切り替えでは、受付コードとアンケートの下書きを保持する。

## 確認結果

- Chrome、モバイルChrome、WebKitの関連E2E **60件すべて成功**。
- 追加の確認用画面では、320 × 568pxの短い画面から、390 × 844px、834 × 1194px、1280 × 800pxまで操作欄の位置を検証。
- 実際のローカル確認用データで、参加申請、受付、アンケートの下書き、通知、証明書、キーボード操作、重大なアクセシビリティ違反の有無を確認。
- 単体テスト86件、構成チェック1件が成功。TypeScript・テスト用ビルド・lint・差分の空白チェックも成功。

追加の表示・操作テストは `e2e/student-experience.spec.ts` にあり、通常の `npm run test:e2e` に含めている。

## 自明な表示・重複する説明の削除

- プロフィールの学生確認済みカード、メール認証完了の説明、主催者の承認済み表示を削除。
- 設定項目の補足文、ログインフォームの入力案内、ホームの挨拶と重複する件数表示を削除。
- 参加履歴の状態説明と進捗図を整理し、状態バッジと実際の待ち順・キャンセル理由を表示。
- 検索の読み込み件数や「まだ表示できるイベントがあります」といった説明を削除。
- 説明未登録時の汎用的な主催者紹介や体験内容を表示しないように変更。
- 初期読み込み中に登録画面の説明が出ないよう、ブランドとスピナーに統一。
- 設定行は説明文の削除に合わせて余白を縮め、390px幅のプロフィール全体を約1,200pxに整理。

この整理後、関連E2E 57件、単体テスト86件、構成チェック1件、ビルド・lintが成功。

## 見た目の統一と装飾の整理

配色と機能を保ち、利用者・団体画面と共通のログイン画面を調整した。
管理者ダッシュボードは対象外。表示の調整は `src/styles/presentation.css` にまとめている。

- 角丸、影、太字の使いすぎを抑え、見出し・本文・補足の強さを整理。
- スマホのイベント一覧、プロフィール、設定、活動履歴を罫線中心にして、囲みの連続を減らした。
- カテゴリは選択中の項目を強調し、未選択の項目は枠を省略。
- プロフィールの興味・イベントのタグを簡素にし、項目ごとの背景装飾を削減。
- 団体ホームの自明な案内文を削除。スマホの管理メニューは矢印付きの行として表示。
- 活動・チャットの表示切り替えは下線で選択状態を示す。
- PCのホームは新着イベントを画像・本文の横並びにして、縦に大きすぎるカードを縮小。
- 44px以上の主要操作領域、フォーカス表示、本文だけがスクロールする詳細画面を維持。

関連E2EはChrome・モバイルChrome・WebKitで **45件成功**。
利用者・団体の実画面と確認用画面を目視確認し、390px幅で横スクロールがないことを確認。
イベント一覧・設定・チャットは320px幅でも既存の操作検証を通過。
TypeScript・テスト用ビルド・lint・差分の空白チェックも成功。

## 一覧・チャット・編集操作の追加修正

- 団体イベント一覧を10件ずつ表示。検索・状態・並び順の変更時は先頭へ戻り、ページ変更時は一覧へフォーカスを移す。初期50件と追加50件の取得方法は維持。
- 390 × 844pxの確認データでは、団体一覧を50件表示していた約9,800pxから、10件表示の2,568pxへ短縮。横方向のはみ出しと44px未満の主要操作ボタンはなし。
- チャットの編集・削除・通報を各投稿の「…」へ集約。上下キー・Home・End・Escape、外側のクリックに対応し、編集・確認ダイアログの終了後は操作ボタンへ戻す。
- メニューは履歴欄内を基準に配置し、短い画面でも入力欄を覆わないよう調整。メッセージ編集にはキャンセルと失敗表示を追加。
- プロフィール編集を背景操作のないダイアログに統一。未保存の変更がある場合だけ、キャンセル・Escape・外側のクリック・ブラウザーの戻るで確認する。戻って編集を続けた場合は下書きを保持。
- 編集中の検索ショートカットで画面が切り替わらないようにし、再読み込み・離脱ではブラウザー標準の入力保護を要求。保存処理中の終了は抑止。
- 画像の切り抜き画面がプロフィール編集画面の上で操作できることも確認。
- 利用者検索でも、絞り込みを解除して元の条件に戻った場合に古いページを再表示しないよう修正。
- READMEの会話例を短くし、PCの一覧・プロフィールはページ全体を撮影。仕様書も2026年11月13日の画面・操作に同期。

この修正後、Chrome・モバイルChrome・WebKitの関連E2E **63件が成功**。画像切り抜き・保存、キーボード操作、重大なアクセシビリティ違反の有無も対象に含む。単体テスト86件とApp Check構成チェック1件も成功。
